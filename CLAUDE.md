# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project type

ServiceNow Fluent application built with `@servicenow/sdk` v4.6.0. App scope: `x_snc_quarterly_ga` (see `now.config.json`). The app tracks quarterly gap-to-plan: Quarters, Quarter Tracking financial metrics, and risk/quarter extensions on the platform CRM Opportunity table.

## Commands

| Command | Purpose |
|---|---|
| `npm run build` | `now-sdk build` — compile Fluent sources to platform metadata |
| `npm run deploy` | `now-sdk install` — install built app to a target ServiceNow instance |
| `npm run transform` | `now-sdk transform` — convert XML/legacy artifacts into Fluent code |
| `npm run types` | `now-sdk dependencies` — regenerate type stubs in `@types/servicenow/` |

There is no test framework configured. There is no separate lint command — TypeScript checking happens via the SDK's build (driven by the project references in `src/fluent/tsconfig.json`).

To work with SDK semantics (metadata conventions, API types, available skills), invoke the `fluent:now-sdk-explain` skill. If the `now-sdk` CLI is not on PATH, run `fluent:now-sdk-setup` first.

## Architecture

**Two TypeScript projects** (composite build via `src/fluent/tsconfig.json` references):

- `src/fluent/` — Fluent metadata sources. Files matching `*.now.ts` are processed by the SDK to generate platform records (tables, business rules, ACLs, dashboards, workspaces, application menus, etc.). These run at build time, not at runtime on the platform.
- `src/server/` — Runtime JavaScript that executes server-side on the platform (ES2022, separate `tsconfig.json` that **excludes `*.now.ts`**). Functions exported from here get embedded into Business Rule scripts.

**Server-side wiring pattern**: A `BusinessRule` in a `*.now.ts` file imports a function from `src/server/` and passes it as `script:`. Example: `business_rules.now.ts` imports `calculateQuarterTrackingMetrics` from `src/server/calculateQuarterTrackingMetrics.js` and attaches it as a before-insert/update BR on the tracking table. The function takes the `current` GlideRecord and mutates it. Keep server code in plain `.js` (or compatible `.ts`) without ES module helpers — `noEmitHelpers: true` and a non-module-aware Glide runtime constrain what is allowed.

**Data model** (all under the `x_snc_quarterly_ga` scope):
- `x_snc_quarterly_ga_quarter` — fiscal quarter (Q1–Q4, fiscal year, active flag).
- `x_snc_quarterly_ga_quarter_tracking` — per-quarter financial metrics. Read-only fields (`new_target`, `pct_build_to_new_target`, `build_to_target_gap`, `variance_to_gap`) are computed by the BR; user-entered fields are `target`, `gap_carryover`, `total_pillar_build`, `total_pillar_upside`, `notes`.
- `sn_opty_mgmt_core_opportunity` — **cross-scope extension** of the platform CRM Opportunity table, adding `x_snc_quarterly_ga_quarter` (reference) and `x_snc_quarterly_ga_risk` (choice). Defined in `opportunity_extensions.now.ts` with `name: "sn_opty_mgmt_core_opportunity" as any` because it's not a table this scope owns.

**UI surfaces** (separate, not interchangeable):
- Classic platform navigation (`navigation.now.ts`) — `ApplicationMenu` + `sys_app_module` records for the legacy nav.
- UX Workspace (`src/fluent/workspaces/gap-analysis/`) — modern workspace at path `gap-analysis`, gated by ACL on `ux_route` for roles `x_snc_quarterly_ga.user` / `.admin` (defined in `list-menu.now.ts`). The workspace's list configuration and dashboard live in sibling files; `dashboard.now.ts` only renders when `visibilities` references `gapAnalysisWorkspace`.

**`Now.ID` keys** are referenced throughout (`Now.ID["gap_analysis_workspace"]`, etc.). The mapping from key name → sys_id is in `src/fluent/generated/keys.ts`, which is **generated by the SDK** during `build`. Do not hand-edit it; if a key is missing, add the `$id: Now.ID["new_key"]` reference in source and rebuild. The numeric `Now.ID[0]` form (used in `business_rules.now.ts`) is an implicit anonymous key.

## Conventions specific to this codebase

- All new tables in this scope must use the `x_snc_quarterly_ga_` prefix. Cross-scope columns added to platform tables use the same prefix as the column name (e.g. `x_snc_quarterly_ga_risk`).
- Computed fields on tracking tables should be marked `read_only: true` in the column definition AND populated by the before-insert/update BR — never trust the client to compute them.
- When adding a new module/widget/list, give it a stable `$id: Now.ID["snake_case_name"]` so the generated sys_id stays consistent across rebuilds.
- Workspace lists must declare `applicabilities` referencing the shared `gapAnalysisApplicability`; otherwise users with the role won't see them.
